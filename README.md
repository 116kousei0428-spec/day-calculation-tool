# 十一 登録管理ツール（Firebase設定組み込み済み）

## 今回の更新
- 提供された Firebase Web アプリ `blow-pos` の接続設定を `config.js` に組み込み済み
- 保存先は **`toichi_shared_v1/records`**。既存POSの保存先とは別のパス
- Firebaseとの接続・読込に成功した場合のみ登録操作を有効化
- 既存POSのルールを消さないため、追加用ルール断片 `firebase-rules-addition.txt` を同梱

## 公開
`index.html` / `main.js` / `config.js` を同じフォルダのまま Cloudflare Pages にアップロード。
ZIP直下にファイルがあるので、ZIPデプロイの場合もそのまま使えます。

## Firebase Realtime Database：最初に確認が必要
Firebaseコンソール → `blow-pos` → Realtime Database → ルール。

既存の `"rules"` オブジェクトに `firebase-rules-addition.txt` のキー `"toichi_shared_v1"` を**追加**して公開してください。既存のPOS用ルールは消さないでください。既存のルール全体を確認できないため、マージ済みの完全なルールファイルは作れません。

既存ルールがすでにこのパスに対して読書き許可を出している場合、追加は不要です。現在のルールは未確認です。設定を変える前に既存ルールをバックアップしてください。

## 主な仕様
- 名前、元金、開始日時、備考の登録
- **単利**：10日（240時間）ごとに元金の10%を加算（元金10万円なら10日後11万円、20日後12万円）
- 登録中・完了一覧、現在金額、合計額
- 完了日時で計算を止める／削除（確認あり）
- Firebase Realtime Database による端末間同期（ルールが許可している場合）
- ログイン機能なし

## 留意点
- 設定情報をコードへ埋め込んだだけでは Firebaseルールの変更や通信成功を保証しません。
- 本環境ではFirebase本番DBへの到達と読み書きを検証できません。デプロイ後、端末2台で登録・完了・削除が同期するか確認してください。
- **リンクを知る人だけに限定できる構成ではありません。**認証なしの公開読書きルールではURLを知らない第三者も、データベース宛に直接アクセス可能です。氏名など個人情報の登録には適しません。
- 既存POSと同じFirebaseプロジェクトを共有するので、アクセスルールの設定時はPOSの既存ルールを維持してください。

## PWA対応（今回追加）
- `manifest.webmanifest`、`sw.js`、192/512pxの「￥」アイコンを追加。
- Cloudflare PagesにZIPを再デプロイした後、Chrome/Edge/Androidの「アプリをインストール」、iOS Safariの「ホーム画面に追加」から追加できます。
- HTTPS配信が必要です（Cloudflare PagesはHTTPS対応）。
- Service Workerはアプリの表示用ファイルのみをキャッシュします。**Firebaseの登録データはオフライン保存しません。** オフライン中は外部Firebaseモジュールの読み込みやDB接続ができず、登録・完了・削除操作は利用できません。
- PWA化による既存Firebase設定・保存先・計算ロジックの変更はありません。
